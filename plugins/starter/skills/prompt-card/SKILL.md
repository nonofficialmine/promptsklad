# prompt-card

Собирает пост для promptsklad из того, что дал пользователь. Ничего не выдумывай: результаты, модели и выводы — только со слов пользователя.

## 1. Узнай недостающее

Обязательны раздел, тема, название и содержимое. Остальное — по желанию.
Спроси одним сообщением только то, чего не хватает. Пользователь не знает ответа — оставь поле пустым.

| Поле в форме | id | Ограничения |
|---|---|---|
| Раздел | section | один, из списка ниже |
| Тема | topic | одна, из списка ниже |
| Название | post_title | 5–80 символов |
| Содержимое | post_body | 20–6000 символов: промпт, конфиг, SKILL.md или описание кейса |
| Для чего | purpose | до 300 символов |
| Как использовать | usage | до 1000 символов |
| Почему работает / выводы | why | до 1000 символов |
| Теги | tags | до 5, из списка ниже |
| Модели | models | до 100 символов, через запятую; только те, на которых пользователь проверял |
| Комментарий | comment | до 1000 символов |
| Имя | author_name | до 40 символов |

Разделы (название в форме → папка): Промпт → prompts, Скилл → skills, Кейс → cases, Хук → hooks, Плагин → plugins, Настройка → settings, MCP → mcp, Агент → agents.

Темы — сфера работы, одна: dev (Разработка), research (Исследования), design (Дизайн), data (Данные и аналитика), content (Тексты и контент), business (Бизнес и продукт), learning (Обучение), other (Другое).

Теги — конкретные задачи и инструменты, до 5: code-review (код-ревью), refactoring (рефакторинг), debugging (отладка), tests (тесты), security (безопасность), docs (документация), automation (автоматизация), ci-cd (CI/CD), git (git), sql (SQL), frontend (frontend), backend (backend), tokens (экономия токенов).

## 2. Проверь

- Ключи, токены и пароли сайт не примет. Замени их заглушкой: `<ваш токен>`, `<пароль>`.
- Содержимое — как есть, без правок смысла. Опечатки исправляй, только спросив.
- Не подходит ни один тег — оставь теги пустыми. Новые теги не придумывай: сайт их не примет.

## 3. Отдай результат

**Основной путь — форма на сайте:** https://promptsklad.vercel.app/new. Регистрация не нужна. Выведи значения по полям формы, каждое отдельным блоком, чтобы их было удобно копировать. Раздел, тему и теги пиши так, как они видны в форме: «Промпт», «Разработка», «код-ревью».

**Пользователь работает с git** — собери файл `posts/<папка>/<slug>.md` и предложи Pull Request в github.com/nonofficialmine/promptsklad. slug — латиница, цифры и дефисы. Формат:

````md
---
title: "<название>"
description: "<для чего: одной строкой, до 160 символов>"
topic: "<id темы>"
tags: ["<id тега>", "<id тега>"]
models: ["<модель>"]
author_name: "<имя>"
---

# <название>

**Тема:** <тема по-русски> · **Теги:** <теги по-русски, через запятую>

**Автор:** <имя>

**Для чего:** <для чего>

**Как использовать:** <как использовать>

```text
<содержимое как есть>
```

**Почему работает:** <почему работает>

**Комментарий:** <комментарий>
````

Правила для файла:
- Пустое необязательное поле — убери его строку целиком: и в frontmatter (шапке между `---`), и в тексте. Исключение: `tags` и `models` в шапке остаются пустыми списками `[]`.
- Значения в шапке — строки JSON: в двойных кавычках, кавычки внутри — `\"`.
- «Тема» и «Теги» в тексте — русские названия из списков выше. Нет тегов — только «Тема».
- Кейс: содержимое — обычным текстом без блока ```` ```text ````, а «Почему работает» называется «Выводы».
- В тексте поста (заголовок и поля после шапки) замени `&` `<` `>` `{` `}` на `&amp;` `&lt;` `&gt;` `&#123;` `&#125;` — иначе страница сломается. Шапку и блок кода не трогай: там всё как есть.
- В содержимом есть ```` ``` ```` — оберни его кавычками на одну больше: ```` ````text ````.
