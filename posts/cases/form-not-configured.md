# Форма отдавала 500, а посты доставили: пробная отправка и обходной путь

**Для чего:** Разобрать, как действовать, когда массовая отправка упирается в поломку на сервере, которую вы не можете починить сами.

Задача: агент через [Playwright MCP](/mcp/playwright-mcp) отправляет 25 постов через публичную форму сайта. Каждая отправка на сервере превращается в Pull Request в репозиторий.

Что случилось: форма отвечала `500 {"error":"not_configured"}`. Поля заполнены верно, капчи нет, антибот-задержка выдержана.

Что сделали:
1. **Пробная отправка.** Агенту дали правило: сначала один пост, при ошибке сервера — стоп. Вместо 25 одинаковых ошибок и нагрузки на сервер получили одну.
2. **Код вместо догадок** — тот же принцип, что в [ts-loop](/skills/ts-loop): сначала корневая причина, потом фикс. Сначала гадали: нет ключа капчи? нет токена? Потом открыли серверный код. Изначально `not_configured` срабатывал, если не задан любой из двух секретов — ключ капчи Cloudflare Turnstile или `GITHUB_TOKEN`. Капчу убрали совсем, и осталось одно условие — пустой `GITHUB_TOKEN`. Все версии, кроме одной, отпали за минуту.
3. **Ошибка с подсказкой.** В ответ сервера добавили имя недостающей переменной: `{"error":"not_configured","missing":["GITHUB_TOKEN"]}`. Следующая проба сразу показала, что токена нет именно в Production-окружении.
4. **Равноценный обходной путь.** Токен добавляет только владелец в Vercel. Но форма в итоге делает PR в `posts/` — значит, тот же результат можно получить через git: ветка с 25 файлами, проверки (формат, лимиты полей, тесты, сборка), один PR. Модерация сохранилась, результат для пользователя тот же.

Почему переменная не подхватывалась (частые причины на Vercel):
- добавлена только для Preview или Development, а не для Production;
- добавлена после сборки без редеплоя: env применяется только к новым деплоям.

**Выводы:** При массовой операции первым шагом — одна проба со стоп-условием. Ошибку сервера быстрее понять, прочитав код, чем перебирая гипотезы. Ошибка должна называть, чего не хватает: это превращает «не работает» в конкретное действие. А если блокер у владельца, ищите путь, который даёт тот же результат, а не ждите.
