# ts-loop: баг не закрыт, пока не доказано, что его нет

**Для чего:** Чтобы Claude не лечил симптом и не объявлял «исправлено» без проверки. Скилл задаёт цикл, который повторяется, пока баг не исчезнет при том же воспроизведении.

**Как использовать:** Создайте .claude/skills/ts-loop/SKILL.md в проекте (или ~/.claude/skills/ts-loop для всех проектов). Claude включит скилл сам, когда найден баг. Вручную: /ts-loop.

```text
---
name: ts-loop
description: Цикл закрытия бага. Используй, как только баг найден — тестом, QA-агентом или пользователем. Корневая причина → минимальный фикс → повтор воспроизведения → если баг остался, цикл заново.
---

# ts-loop

Баг не закрыт, пока не доказано, что его нет.

1. INVESTIGATE — найди корневую причину, а не симптом.
   - Воспроизведи баг стабильно, запиши шаги.
   - Сформулируй гипотезу о причине.
   - Подтверди её временными логами в ключевых точках: вход в функцию, ветвления, до и после изменения состояния, ответ API, полный объект ошибки.
   - Для UI: консоль, сетевые запросы, DOM (через Playwright MCP или DevTools).
2. RESEARCH — варианты исправления; выбери минимальный, направленный на причину.
3. APPLY — минимальное изменение, без попутного рефакторинга.
4. TEST — повтори ровно те же шаги из пункта 1. Доказательство: вывод теста, скриншот, лог, статус ответа. Проверь соседние негативные случаи.
5. Решение:
   - баг остался → гипотеза была неверна или неполна → снова пункт 1;
   - баг исчез → убери временные логи, запиши, что исправлено и чем доказано.

Проверка причины: если убрать найденную причину, баг должен исчезнуть. Не исчез — причина не найдена.

Перед коммитом: в git diff не должно быть новых console.log / print. Остаётся только структурный логгер.

Честность: не пиши «кажется, исправлено». Нет доказательства — баг не закрыт.

Лимит: 3–5 полных циклов. Не закрылся — остановись и опиши: какие гипотезы проверены, что исключено, текущая лучшая гипотеза.
```

**Почему работает:** Без цикла Claude правит первое правдоподобное место и сообщает об успехе. Повтор тех же шагов воспроизведения и проверка «убрал причину — баг исчез» отличают найденную причину от совпадения. Лимит циклов не даёт крутиться бесконечно на неверной гипотезе.

**Когда не работает:** На плавающих багах (гонки, нестабильная сеть) одно воспроизведение ничего не доказывает. Нужно повторять много раз и смотреть на частоту.
