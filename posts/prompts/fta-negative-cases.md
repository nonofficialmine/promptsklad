# Негативные тест-кейсы через дерево отказов (FTA)

**Для чего:** Получить полный список негативных и пограничных кейсов для фичи. Обычно их придумывают интуитивно и пропускают половину. Дерево отказов (Fault Tree Analysis) даёт их систематически: каждый лист дерева — тест-кейс.

**Как использовать:** Вставьте промпт, ниже — описание фичи или тикет.

```text
Построй дерево отказов (FTA) для фичи ниже.

1. Корень — нежелательное событие: «пользователь не получил результат фичи».
2. Раскладывай вниз через ИЛИ (любая причина достаточна) и И (отказ только при совпадении причин).
3. Покрой уровни: ввод пользователя, интерфейс, сеть, бэкенд, данные, параллельные действия (две вкладки, двойной клик), права доступа, удалённые/изменённые связанные объекты.
4. Останавливай ветку, когда лист можно проверить одним тестом.
5. В конце — таблица: лист → тест-кейс (шаги, ожидаемый результат) → приоритет.

Не добавляй ветки, которых не может быть в этой системе.

Фича: [описание]
```

**Почему работает:** В отличие от «5 почему», которое даёт одну цепочку, дерево заставляет перебрать все ветки и видит комбинации (отказ только при A и B вместе). Явные уровни в пункте 3 не дают застрять на одном слое, например только на валидации формы.

**Когда не работает:** Не находит отказы, о существовании которых никто не подозревает. Для этого нужно исследовательское тестирование руками.
