# Session Orchestrator: план, волны агентов и проверка перед коммитом

**Тема:** Разработка · **Теги:** автоматизация, тесты, git

**Для чего:** Для тех, кто ведёт с Claude Code длинные сессии и хочет порядка: сначала согласованный план, потом работа волнами параллельных агентов с тестами после каждой волны, в конце сверка с планом, коммит и задачи на остаток.

**Как использовать:** Нужны Node.js 24 или новее и git-репозиторий. Введите две команды установки в Claude Code. Затем один раз выполните /bootstrap: он создаст служебную папку .orchestrator и допишет блок Session Config в CLAUDE.md — проверьте в нём команды тестов, проверки типов и линтера (test-command, typecheck-command, lint-command). Короткий путь без вопросов: /bootstrap --fast --no-interview. Дальше рабочий цикл: /session feature — агент читает репозиторий и задачи и предлагает объём работы, вы его правите; /go — выполнение волнами с тестами после каждой; /close — сверка, коммит и задачи на остаток. Чтобы заводить задачи, нужен gh (GitHub) или glab (GitLab) с выполненным входом. На Windows автор плагин не тестирует: хукам нужен Git Bash или WSL. По желанию: /plugin install so-hud@kanevry добавит строку статуса сессии.

```text
/plugin marketplace add Kanevry/session-orchestrator
/plugin install session-orchestrator@kanevry

/bootstrap
```

**Почему работает:** По подсчёту автора, внутри 51 навык, 30 слеш-команд, 14 субагентов и хуки на 10 типов событий, плюс MCP-сервер с двумя инструментами только для чтения. Главное — цикл /session, /go, /close. Каждому агенту в волне выдаётся список файлов, которые ему можно менять, а пересекающиеся списки отклоняются заранее, так что агенты не затирают работу друг друга. Хук-охранник блокирует 12 опасных шаблонов команд (жёсткий reset, rm -rf, force-push, DROP TABLE и другие). Прогресс пишется в .claude/STATE.md, поэтому после сбоя следующая /session предложит продолжить с последней завершённой волны. Есть и дополнительные команды: /plan, /brainstorm и /grill для сырых идей, /debug для поиска причины ошибки, /test и /test-audit для тестов, /repo-audit для оценки репозитория, /evolve для выводов из прошлых сессий, /autopilot для цепочки сессий.

**Комментарий:** Плагин стороннего автора: Bernhard Goetzendorfer, github.com/Kanevry/session-orchestrator. promptsklad его не проверял — перед установкой посмотрите репозиторий. Хуки срабатывают сами: при старте и конце сессии, до и после вызова инструментов, при запуске и остановке субагентов. /close сам делает коммиты и через gh или glab заводит задачи в вашем GitHub или GitLab. При старте сессии плагин делает анонимный запрос к реестру npm, чтобы проверить обновления; это отключается переменной SO_DISABLE_UPDATE_CHECK=1 или DO_NOT_TRACK=1. Анонимная телеметрия есть, но выключена, пока вы явно не согласитесь. Служебные файлы (.orchestrator, .claude/STATE.md) пишутся в репозиторий и остаются после удаления плагина. Лицензия MIT.
