# Archcore: спецификации и решения проекта в Git для агента

**Тема:** Разработка · **Теги:** документация, код-ревью, git

**Для чего:** Для тех, кто устал заново объяснять агенту устройство проекта: Archcore хранит спецификации, решения, правила и планы в Git, в папке .archcore, и выдаёт агенту нужное, чтобы правки совпадали с архитектурой и прошлыми решениями.

**Как использовать:** Сначала поставьте утилиту archcore: без неё MCP-сервер и хуки плагина не работают. Её ставит скрипт с сайта archcore.ai (для macOS, Linux и WSL, отдельно для Windows через PowerShell), точные команды есть в README. Затем введите две команды установки плагина в Claude Code. В проекте выполните /archcore:init — он подключит проект и предложит первые документы одним предпросмотром; если у вас уже есть CLAUDE.md или AGENTS.md, команда /archcore:init import превратит их в документы. Дальше три основные команды: /archcore:plan перед работой над фичей (спецификация и план задач), /archcore:document чтобы записать решение или описать модуль, /archcore:review перед слиянием ветки. По словам автора, работают и обычные фразы — например, попросить спланировать фичу или проверить ветку. Документы лежат в .archcore в виде Markdown.

```text
/plugin marketplace add archcore-ai/archcore
/plugin install archcore@archcore-plugins

/archcore:init
```

**Почему работает:** Внутри навыки init, plan, document и review, два субагента — archcore-assistant для задач с несколькими документами и archcore-auditor для проверки базы знаний (только чтение), — и MCP-сервер archcore для поиска и правки документов. /archcore:plan сначала читает репозиторий и существующие документы, спрашивает только то, чего там нет, и сам оценивает размер изменения от S до XL: мелкой правке документы не нужны, новой возможности — спецификация и план, крупной инициативе — ещё и PRD. /archcore:review сравнивает ветку с документами в обе стороны и для каждого расхождения говорит, что неверно — код или спецификация. Хуки при старте сессии подгружают контекст, перед записью файлов охраняют документы и подсказывают, совпадает ли правка с правилами, а после изменения документов проверяют их. Знания проекта переживают сессию и проходят ревью как обычный код.

**Комментарий:** Плагин стороннего автора: Archcore, github.com/archcore-ai/archcore. promptsklad его не проверял — перед установкой посмотрите репозиторий. Сам плагин лежит в папке plugins/archcore. Утилита archcore ставится скриптом, который запускается прямо из интернета, — сначала прочитайте его. Хуки срабатывают сами при старте сессии и перед каждой записью файлов. По политике конфиденциальности автора документы остаются в репозитории, но установщик и утилита отправляют анонимные события об установке и обновлении (версия и платформа), а сама утилита обновляется в фоне не чаще раза в сутки. Аналитику отключают переменной DO_NOT_TRACK=1 или ARCHCORE_TELEMETRY_OPTOUT=1, самообновление они не выключают. /archcore:init дописывает свой блок в CLAUDE.md или AGENTS.md. Лицензия Apache 2.0.
