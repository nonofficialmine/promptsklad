# Claude Code Harness: чертёж обвязки для своего ИИ-агента

**Тема:** Разработка

**Для чего:** Для разработчиков, которые строят своего ИИ-агента: навык помогает продумать не промпт, а всё, что вокруг модели, — как собирается запрос, как идёт цикл работы, какие инструменты и права доступа, что хранится в памяти и как восстановиться после сбоя.

**Как использовать:** Введите две команды установки в Claude Code. Навык вызывается командой /claude-code-harness:claude-code-harness — можно сразу с описанием задачи, например попросить спроектировать обвязку для агента, который пишет код в репозитории, с правами доступа и восстановлением. На выходе — текстовый чертёж: цель системы и границы делегирования, слои, сборка запроса, цикл хода, инструменты и права, память и контекст, журнал и восстановление, точки расширения (плагины, MCP, субагенты) и порядок сборки. Ничего дополнительно ставить не нужно. Автор прямо оговаривает, что навык не для простых промптов, мозговых штурмов о продукте или обычного написания кода.

```text
/plugin marketplace add dadwadw233/claude-code-harness
/plugin install claude-code-harness@claude-code-harness

/claude-code-harness:claude-code-harness
```

**Почему работает:** Внутри один навык claude-code-harness и четыре справочных файла: принципы обвязки (harness-principles.md), словарь шаблонов вроде сборщика запроса и плоскости восстановления (harness-pattern-language.md), шаблон итогового чертежа (harness-blueprint-template.md) и выводы, обобщённые из устройства Claude Code (claude-code-derived-insights.md). Навык заставляет явно описать то, что обычно откладывают: где живут разрешения и подтверждения, что делать при частичном сбое, какая память переживает перезапуск, как человек видит и останавливает работу агента. Это помогает не застрять на схеме «промпт плюс список инструментов» и честно решить, нужна ли сложная обвязка или хватит простого скрипта.
